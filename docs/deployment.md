# Deploying OpsDesk AI (Vercel + Render)

| Part | Where | Why |
| --- | --- | --- |
| React frontend | **Vercel** | Static Vite build, global CDN |
| Express API + webhook worker | **Render** (web service, Docker) | Needs an always-running server; Vercel functions stop after each request, which would stop webhook delivery and retries |
| PostgreSQL | **Render** (managed Postgres) | Created and wired automatically by the Blueprint |
| n8n | Any **publicly reachable** n8n | A cloud API cannot reach an n8n running on your PC |

```
Browser ──HTTPS──▶ Vercel ──/api/*──▶ Render (Express API) ──▶ Render PostgreSQL
                     │                    │
                     └─ static React app  └──signed webhooks──▶ n8n ──▶ Gmail
```

Vercel forwards `/api/*` to Render ([`frontend/vercel.json`](../frontend/vercel.json)), so the browser only ever talks to your Vercel domain. The session cookie stays first-party (`HttpOnly; Secure; SameSite=Lax`) and no cross-site cookie or CORS setup is needed.

> Production differs from the local demo on purpose: **no demo accounts**. You create your own administrator, and optionally load the sample help articles.

---

## 1. Deploy the API and database on Render

1. Sign in at https://render.com with your GitHub account.
2. **New → Blueprint**, pick the `OpsDesk-AI` repository. Render reads [`render.yaml`](../render.yaml) and proposes:
   - `opsdesk-api`: the API, built from `backend/Dockerfile`; migrations run automatically on every deploy
   - `opsdesk-db`: PostgreSQL 17
3. Fill in the values Render asks for:

   | Variable | Value |
   | --- | --- |
   | `GEMINI_API_KEY` | your Gemini key |
   | `CORS_ORIGINS` / `APP_BASE_URL` | your Vercel URL. You don't know it yet, so enter `https://example.com` for now and fix it in step 4 |
   | `N8N_WEBHOOK_URL` / `N8N_WEBHOOK_SECRET` | leave empty for now (events are recorded as "skipped") or see step 5 |

   `SESSION_SECRET` is generated by Render. `NODE_ENV=production`, `COOKIE_SECURE=true` and `TRUST_PROXY=2` are preset.
4. **Apply**. When the deploy is green, open `https://<your-service>.onrender.com/api/health`. It should show `{"data":{"status":"ok","database":"ok",…}}`.

Note the service URL. If Render gave it a different name than `opsdesk-api.onrender.com`, update the `/api/:path*` destination in `frontend/vercel.json` to match, then commit and push.

## 2. Create your administrator and load the help articles

Run the one-time setup scripts from your PC against the Render database:

1. In Render, open **opsdesk-db → Connect** and copy the **External Database URL**.
2. In PowerShell, in the project folder (replace the placeholders; use a strong password with at least 12 characters, letters and a number):

   ```powershell
   $env:OPSDESK_SKIP_ENV_FILE = "1"
   $env:NODE_ENV = "production"
   $env:DATABASE_URL = "<External Database URL>?sslmode=require"
   $env:ADMIN_EMAIL = "you@yourcompany.com"
   $env:ADMIN_NAME = "Your Name"
   $env:ADMIN_PASSWORD = "<a strong password>"
   npm --prefix backend run admin:create
   npm --prefix backend run seed:kb
   Remove-Item Env:ADMIN_PASSWORD, Env:DATABASE_URL
   ```

   - `admin:create` refuses weak passwords and existing emails.
   - `seed:kb` publishes the 9 sample troubleshooting articles (no accounts, tickets or assets) and skips any that already exist. The articles describe a fictional company, so edit them in the Knowledge Base before relying on them.
   - The demo seed (`db:seed`) refuses to run in production.

## 3. Deploy the frontend on Vercel

1. Sign in at https://vercel.com with GitHub, then **Add New → Project** and import `OpsDesk-AI`.
2. Set **Root Directory** to `frontend`. Vercel detects Vite. No environment variables are needed: the build contains no secrets.
3. **Deploy** and note your URL, e.g. `https://opsdesk-ai.vercel.app`.

## 4. Point the API at your Vercel URL

In Render → `opsdesk-api` → **Environment**, set `CORS_ORIGINS` and `APP_BASE_URL` to your Vercel URL (no trailing slash) and save. Render redeploys.

Open your Vercel URL and sign in with the administrator from step 2.

## 5. Connect n8n (optional)

n8n must be reachable from the internet. You can self-host it (as on your PC, on a server or a Render service with a persistent disk) or use n8n Cloud.

1. Import `n8n/opsdesk-ticket-notifications.workflow.json`, connect a Gmail credential and **publish** it. Google needs the new n8n address as an authorized redirect URI: `https://<your-n8n-host>/rest/oauth2-credential/callback`.
2. Generate a secret:
   ```powershell
   node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
   ```
3. On **n8n**, set these environment variables, exactly as in [docs/n8n.md](n8n.md):
   ```
   OPSDESK_WEBHOOK_SECRET=<the secret>
   N8N_BLOCK_ENV_ACCESS_IN_NODE=false
   NODE_FUNCTION_ALLOW_BUILTIN=crypto
   ```
   If your n8n plan doesn't let you set environment variables, self-host n8n instead. The workflow's signature check needs them.
4. On **Render**, set `N8N_WEBHOOK_URL=https://<your-n8n-host>/webhook/opsdesk-events` and `N8N_WEBHOOK_SECRET=<the same secret>`.
5. In OpsDesk, **Settings → Integrations → Send test event**. It should show **Delivered**.

## 6. Check the deployment

- [ ] `/api/health` reports `ok`
- [ ] Sign-in works on the Vercel URL. A wrong password shows "Invalid email or password"
- [ ] The AI assistant answers "My printer is offline" with a source link (needs `seed:kb` and `GEMINI_API_KEY`)
- [ ] Creating a ticket shows a readable ID such as `OPS-2026-0001`
- [ ] Settings → Integrations shows the AI as configured and (if set up) the test event as delivered

## Good to know

- **Free plans.** A free Render web service goes to sleep when idle, so the first request takes a while and webhook retries wait until it wakes. Free databases may have time or size limits. Check Render's current plan details, and use paid plans for anything beyond a demo.
- **Updating.** Pushing to `main` redeploys both Vercel and Render, and migrations run automatically.
- **Secrets** live only in the Render and Vercel dashboards. Never commit `.env`.
- **What was verified locally** before writing this guide, with `NODE_ENV=production`, `COOKIE_SECURE=true`, `TRUST_PROXY=2` and requests forwarded the way Vercel and Render forward them:
  - migrations
  - `admin:create`, including weak-password and duplicate rejection
  - `seed:kb`, including a safe re-run
  - the demo seed refusing to run
  - startup refusing insecure cookies
  - Secure + HttpOnly session cookie over HTTPS, and no cookie over plain HTTP
  - per-client sign-in rate limiting behind two proxies
  - grounded Gemini answers from the seeded articles

  The deploys to Vercel and Render themselves happen in your accounts and could not be tested from here.
